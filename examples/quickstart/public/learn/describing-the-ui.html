Describing the UI

rephp is a library for rendering user interfaces. A UI is built from small units like buttons, text and images. rephp lets you combine them into reusable, nestable components.

Importing and exporting components#

You can declare many components in one file. When an app grows, put the reusable components in their own files and compose them in a page. React uses export and import for this. rephp uses PHP namespaces:

  • Put the shared components in src/components/, in the namespace App\Components. Files outside src/pages/ are not routes.
  • In the page file, import a function component with use function App\Components\{Layout, Profile};.
  • Import a class component with use App\Components\LikeButton;.
  • A component in the same namespace needs no import. Profile uses <LikeButton /> without an import.

The page Gallery.rhp below uses components from three other files. Layout is the page shell: it gets the page content as children and a named slot <Layout:footer>. Each LikeButton keeps its own state. Click the tabs to see each file:

The compiler finds the component of each tag at build time, with the PHP rules: first a use function import, then a use import of a class, then the current namespace. It checks the props across files too: an unknown component or prop is an error (E010, E011), with the .rhp line of the tag.

Reading data from a database#

In Gallery.rhp, the scientists are a PHP array, and each like is browser state: a reload clears it. In a real app, the data comes from a database. Components render on the server, so a component can read the database directly. You do not need an API between them.

The page DurableGallery.rhp below is the same gallery, with the data in SQLite. It uses Doctrine DBAL:

  • src/data/Scientists.rhp is the data layer. It is plain PHP, with no markup. It makes the database file var/data/gallery.sqlite on the first call.
  • The page reads the rows with Scientists::all() while it renders. It reuses Layout and Avatar from the files above.
  • The handlers write to the database. LikeCounter calls Scientists::like(), and AddScientist calls Scientists::add().
  • After a handler, the server renders the page again. It reads the new rows and morphs only the components that changed.

Click a like button, add a scientist, then click Reset or open the page in another browser. The data stays. Only the error message of the form is browser state (useState), because it is for one visitor only.

The key on LikeCounter is the row id. The server finds the handler of an event by the position of the component in the tree. With a key, a click goes to the correct row, also when the rows change between the page load and the click (for example, when a row is deleted).

One connection for each server process

rephp serve is one long-running process, so Scientists opens the connection once and keeps it. The queries are synchronous: a slow query blocks the event loop. SQLite on a local file is fast. For a remote database, keep the queries short.
